# NEXUS-SIGN: демонстрационный банк. Полная инструкция по запуску

Песочница показывает работу NEXUS-SIGN внутри банка. Её части работают вместе:

- **банковское приложение на телефоне** (iPhone и Android), внутри которого встроен NEXUS-SIGN SDK;
- **сервер банка** со счетами, картами, учётом двойной записью, комиссиями и квитанциями;
- **Auth Core** — неизменённый сервер авторизации NEXUS-SIGN; печати доказательств ставит тестовый HSM SoftHSM;
- **консоль банка** на компьютере: в ней видно каждую операцию, пока клиент подтверждает её на телефоне.

Все деньги тестовые, клиенты вымышленные. Песочница изолирована: у неё своя сеть, своя база и свои пароли, и к рабочим системам она не подключается.

## 0. Один раз перед началом

1. **Примите код в основную ветку.** Откройте https://github.com/ptrvalina/nexus-sign/pull/26, нажмите **Ready for review**, затем **Merge pull request**. Если вливать пока не хотите, работайте прямо с веткой `sandbox/bank-platform-m1` (шаг 2.2).
2. **Удалите на GitHub старую ветку `sandbox/bank-platform`.** В её истории есть строка, которую сканер секретов ошибочно принимает за ключ, и пока ветка существует, проверка безопасности будет падать. Удалить можно в списке веток (Branches → корзина) или в терминале:
   ```
   git push origin --delete sandbox/bank-platform
   ```

## 3. Запустить песочницу

```bash
cd ~/nexus-sign
sandbox/bin/sandbox up
```

Первый запуск занимает 5–15 минут: собираются SoftHSM, Auth Core и банк. Последующие запуски проходят за секунды.

Перед стартом команда сама проверяет изоляцию: своя база, свой Redis, нет адресов push и SMS, версия Auth Core совпадает с зафиксированной. Если какая-то проверка не прошла, песочница не запустится и объяснит почему (см. раздел 10).

В конце команда напечатает:

```
Bank console:   http://127.0.0.1:8190   (operator / <пароль консоли>)
Device port:    http://127.0.0.1:8191   (bank app; customers anna, piotr / <пароль клиентов>)
```

Запишите оба пароля. Они создаются один раз и потом лежат в файлах:

- пароль консоли: `sandbox/.state/console-password`
- пароль клиентов `anna` и `piotr`: `sandbox/.state/customer-password`

Показать их можно так: `cat sandbox/.state/console-password sandbox/.state/customer-password`.

## 4. Консоль банка (на Mac)

Откройте в браузере **http://127.0.0.1:8190** и войдите как `operator` с паролем консоли.

| Раздел | Что показывает |
|---|---|
| Обзор | состояние Auth Core, число клиентов, ожидающие и исполненные операции |
| Клиенты | клиенты, их устройства в Auth Core и проверка цепочки доказательств |
| Счета и карты | балансы, карты и проверка учёта: сумма всех проводок всегда 0 |
| Транзакции | каждая операция с **хронологией** от создания до квитанции; здесь же отмена и ввод офлайн-кода |
| Сессии авторизации | запросы подтверждения в Auth Core |
| Доставка уведомлений | что банк отправил в приложение и когда приложение это забрало |
| Доказательства | закреплённый ключ печати HSM и проверка каждой записи банком |
| Политики | комиссии, лимиты, срок подтверждения |
| Журнал аудита | все события; таблицу можно только дописывать |
| Состояние системы | Auth Core, HSM (SoftHSM — тестовый), ревизия, проверки учёта |
| Сценарии | 15 автоматических демонстраций; кнопка «Запустить» у каждой |

Все сценарии разом можно прогнать из терминала: `sandbox/bin/sandbox scenarios`. Каждый должен закончиться `PASSED`.

## 5. Подготовить подключение телефонов по Wi‑Fi

Телефоны обращаются к Mac по Wi‑Fi. NEXUS-SIGN SDK разрешает только HTTPS, поэтому песочнице нужен свой сертификат.

1. Подключите Mac и телефон к **одной сети Wi‑Fi**.
2. Узнайте IP-адрес Mac:
   ```bash
   ipconfig getifaddr en0
   ```
   Например, `192.168.0.118`. Дальше вместо него подставляйте свой адрес.
3. Создайте сертификат и перезапустите песочницу. После этого она будет доступна из Wi‑Fi и останется доступной при следующих запусках:
   ```bash
   sandbox/bin/sandbox cert 192.168.0.118
   sandbox/bin/sandbox up
   ```
   Команда `up` напечатает адрес для приложений: `Device port: https://192.168.0.118:8191`.
4. Адрес банка для приложений: **https://192.168.0.118:8191**.
5. Если macOS спросит, разрешить ли Docker входящие подключения, нажмите «Разрешить».

> Если IP-адрес Mac сменился (другая сеть или роутер выдал новый), повторите шаг 3 с новым адресом и заново установите сертификат на телефоны.

## 6. iPhone

### 6.1 Установить сертификат песочницы

1. Отправьте файл `~/nexus-sign/sandbox/.state/tls/ca.crt` на iPhone через AirDrop (или себе на почту).
2. На iPhone: **Настройки → Профиль загружен → Установить** (введите код телефона).
3. Затем: **Настройки → Основные → Об этом устройстве → Доверие сертификатам**. Включите доверие для «NEXUS-SIGN Sandbox CA».

### 6.2 Собрать и установить приложение (бесплатный Apple ID)

1. Откройте в Xcode файл `~/nexus-sign/sandbox/mobile/ios/VoxTelBank.xcodeproj`.
2. **Xcode → Settings → Accounts**: добавьте свой Apple ID.
3. Слева выберите проект **VoxTelBank**, цель **VoxTelBank**, вкладка **Signing & Capabilities**:
   - **Team**: «ваше имя (Personal Team)»;
   - если Xcode скажет, что идентификатор занят, поменяйте **Bundle Identifier** на свой, например `com.aliaksei.voxtel.bank`.
4. Подключите iPhone кабелем и разблокируйте его. Если Xcode попросит, включите на телефоне **Настройки → Конфиденциальность и безопасность → Режим разработчика** (телефон перезагрузится).
5. Вверху Xcode выберите свой iPhone и нажмите **▶ Run**.
6. При первом запуске iPhone скажет «Ненадёжный разработчик». Разрешите: **Настройки → Основные → VPN и управление устройством → ваш Apple ID → Доверять**. Затем запустите приложение снова.

> С бесплатным Apple ID приложение работает 7 дней. Потом снова нажмите Run в Xcode: данные и подключение NEXUS-SIGN сохранятся.

### 6.3 Первый вход

1. Откройте **VoxTel Demo**. Внизу экрана входа нажмите «Адрес банка» и введите `https://192.168.0.118:8191`.
2. Логин **anna**, пароль клиентов из шага 3, затем «Продолжить».
3. Приложение предложит **«Подключить телефон»**. Нажмите и подтвердите Face ID. Ключ подписи создаётся в Secure Enclave и никогда не покидает iPhone.
4. Откроется главный экран: счета, карта, быстрые действия, операции.

## 7. Android

Есть два способа подключения. **Б** проще, если сертификат из раздела 5 ещё не создан.

### 7.1 Получить приложение (APK)

- **Готовый APK.** В PR #26 откройте вкладку **Checks**, задание «sandbox / Android bank app APK», раздел **Artifacts**, и скачайте `voxtel-sandbox-bank-apk`. Внутри архива файл `app-debug.apk`.
- **Или соберите сами.** Нужна Java 17:
  ```bash
  cd ~/nexus-sign/sandbox/mobile/android
  sh ../../../android-sdk/gradlew assembleDebug
  # файл: app/build/outputs/apk/debug/app-debug.apk
  ```

### 7.2 Установить

1. На телефоне включите режим разработчика: **Настройки → О телефоне → 7 раз нажать «Номер сборки»**. Затем **Для разработчиков → Отладка по USB**.
2. Подключите телефон кабелем к Mac и разрешите отладку на экране телефона.
3. Установите приложение:
   ```bash
   adb install -r app-debug.apk
   ```

### 7.3 Подключиться к банку

- **А. По Wi‑Fi (как iPhone).** Перенесите `ca.crt` на телефон. Установите его: **Настройки → Безопасность → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС**. Путь в меню зависит от производителя. Адрес банка в приложении: `https://192.168.0.118:8191`.
- **Б. По USB, без сертификата.** Работает, только если сертификата нет: команда `cert` не запускалась, или его убрали командой `sandbox/bin/sandbox cert --remove` и затем запустили `up`. Порт тогда работает по HTTP:
  ```bash
  adb reverse tcp:8191 tcp:8191
  ```
  Адрес банка в приложении: `http://127.0.0.1:8191`. Команду `adb reverse` нужно повторять после каждого переподключения кабеля.

  Если сертификат уже создан, используйте `https://localhost:8191`. Сначала установите `ca.crt` на телефон, как в способе А.

### 7.4 Вход

Войдите как **piotr** с паролем клиентов и нажмите «Подключить телефон». Ключ создаётся в аппаратном хранилище телефона (StrongBox или TEE).

> Один клиент — один телефон. Если войти одним клиентом с двух телефонов, второй запустит замену устройства с задержкой безопасности 2 минуты. Для показа удобнее давать iPhone клиенту `anna`, а Android — клиенту `piotr`.

## 8. Демонстрация: что показывать

Откройте рядом консоль банка (раздел «Транзакции») и телефон.

### 8.1 Обычный перевод

1. Телефон: **Платежи → Новый платёж**. Получатель — любое избранное (например «Ион Попеску») или IBAN другого клиента: у Петра `MD90VI000022241100000001`. Сумма, например, 50.
2. **Оплатить**. Экран проверки покажет сумму, комиссию и итог (как в макете). Нажмите **Подтвердить**.
3. Откроется **«Подтвердите перевод в VoxTel»**. Данные на этом экране SDK прочитал из тех байтов, которые подписывает ключ телефона. Нажмите **Подтвердить**, затем Face ID или отпечаток.
4. Экран «Ожидание подтверждения», затем «Переведено успешно». Квитанцию и сохранение в избранное можно открыть оттуда же.
5. В консоли откройте операцию: все 11 шагов хронологии зелёные. Банк сам проверил печать HSM и подпись, сверил условия со своей записью, провёл учёт и выдал квитанцию.

### 8.2 «Это не я»

Создайте платёж и в окне подтверждения нажмите **«Это не я»**. Операция будет отклонена, денег не спишется, в консоли статус `REJECTED`.

### 8.3 Подтверждение без интернета (код для банка)

1. Создайте платёж. В окне подтверждения нажмите **«Нет интернета? Код для банка»** и подтвердите биометрией. Приложение покажет 8 цифр.
2. Включите на телефоне **авиарежим**.
3. В консоли откройте эту операцию, введите код и нажмите «Ввести код». Статус станет «код принят, ждём подпись». **Операция не исполняется**, пока банк не получит подпись телефона.
4. Выключите авиарежим. Приложение само отправит подпись, и операция станет «Выполнено».

### 8.4 Автоматические сценарии

**Консоль → Сценарии → Запустить.** Здесь показаны неверная подпись, подменённые данные, истёкший запрос, отмена, сбой уведомления, обрыв сети, дубли и идемпотентность, QR, проверка цепочки доказательств. Сторону клиента играет программное тест-устройство, и в консоли оно так и подписано.

## 9. Остановить, сбросить, удалить

```bash
sandbox/bin/sandbox down          # остановить, данные сохраняются
sandbox/bin/sandbox up            # запустить снова
sandbox/bin/sandbox reset         # удалить данные песочницы: следующий up начнёт с чистыми демо-данными
sandbox/bin/sandbox remove --yes  # удалить контейнеры, тома, образы и sandbox/.state полностью
sandbox/bin/sandbox status        # что запущено
sandbox/bin/sandbox logs bank     # журнал банка (или auth-core, postgres)
```

После `reset` войдите в приложение заново и снова нажмите «Подключить телефон»: старое подключение песочница больше не знает. Пароли из `sandbox/.state` сохраняются; `remove --yes` удаляет и их.

## 10. Если что-то не работает

| Признак | Что сделать |
|---|---|
| `Docker is not running` | запустите Docker Desktop и дождитесь зелёного статуса |
| `Auth Core … is not the revision in sandbox/PINNED_AUTH_CORE` | код Auth Core изменился. Для пробы: `sandbox/bin/sandbox up --allow-unpinned`. Чтобы зафиксировать проверенную версию: `sandbox/bin/sandbox pin` |
| `port is already allocated` (8190 или 8191) | порт занят: `SANDBOX_CONSOLE_PORT=8290 SANDBOX_DEVICE_PORT=8291 sandbox/bin/sandbox up`. В приложении тогда укажите порт 8291 |
| iPhone: «Нет связи с банком» | телефон и Mac в одной сети Wi‑Fi? Сертификат установлен **и** доверие включено (6.1)? После `cert` песочница перезапущена командой `up`? В Safari на iPhone должен открываться `https://<IP>:8191/healthz` |
| Сменился IP-адрес Mac | `sandbox/bin/sandbox cert <новый IP>`, затем `sandbox/bin/sandbox up`, и снова установите `ca.crt` на телефоны |
| Xcode: «Failed to register bundle identifier» | поменяйте Bundle Identifier на свой (6.2, шаг 3) |
| iPhone: приложение перестало открываться через 7 дней | так работает бесплатный Apple ID: подключите телефон и снова нажмите Run в Xcode |
| Android: «Нет связи с банком» по USB | повторите `adb reverse tcp:8191 tcp:8191`. Без сертификата адрес `http://127.0.0.1:8191`; с сертификатом — `https://localhost:8191` и установленный `ca.crt` |
| «Замена телефона ожидает подтверждения» | этот клиент уже подключён на другом телефоне. Подождите 2 минуты или используйте другого клиента |
| Сценарий в консоли `FAILED` | откройте его запуск: там шаги и причина. Журнал банка: `sandbox/bin/sandbox logs bank` |
| Всё запуталось | `sandbox/bin/sandbox reset` и затем `sandbox/bin/sandbox up` |

## 11. Что пока не входит

- **Аудио- и видеоэскалация** (робот-звонок из макета) — следующая веха. Сейчас эти сценарии помечены как недоступные; ничего не имитируется.
- **SMS-код** (экран из макета). В Auth Core нет SMS-канала, поэтому в демо его нет.
- **Push-уведомления.** Для них нужны платный Apple Developer и проект Firebase. Сейчас приложение раз в 3 секунды само спрашивает банк, нет ли запросов.
- **Вход по подтверждению «Подтвердите вход в VoxTel»** из макета: вход сейчас по логину и паролю.
