# Демо-банк для тестировщиков из любой точки мира

Эта инструкция — продолжение [INSTRUCTION.ru.md](INSTRUCTION.ru.md). Здесь песочница переезжает на сервер в интернете. Тестировщик где угодно в мире ставит приложение (iPhone — через TestFlight, Android — файлом со страницы банка), входит своим логином, и его операции видны в консоли банка.

```
Телефон тестировщика ──HTTPS──▶ https://demo.ваш-домен      банк: приложение, страница скачивания
Вы (браузер)         ──HTTPS──▶ https://console.demo.ваш-домен   консоль банка (два пароля)
                                 └── на сервере: Caddy → банк → Auth Core + SoftHSM, PostgreSQL, Redis
```

Сертификаты выпускает Let's Encrypt, бесплатно и автоматически. Тестировщикам **ничего не нужно устанавливать, кроме приложения**.

---

## Что купить и оформить

| Что | Стоимость | Кто делает |
|---|---|---|
| Сервер (VPS): Ubuntu 24.04, 2–4 vCPU, **4 ГБ памяти**, 40 ГБ диска | примерно 5–10 € в месяц | вы |
| Домен (например `voxtel-demo.com`) или поддомен вашего существующего | от ~10 $ в год | вы |
| Аккаунт Apple Developer на компанию — для TestFlight | 99 $ в год | вы: оплата и проверка Apple |
| Для Android | бесплатно: APK раздаётся со страницы банка | — |

Подойдёт любой провайдер VPS, у которого можно оплатить и создать сервер с Ubuntu 24.04. Важно, чтобы у сервера был постоянный публичный IPv4-адрес и были открыты порты 22, 80 и 443.

---

## Шаг 1. Сервер

1. Создайте сервер с **Ubuntu 24.04** и запишите его IP-адрес, например `203.0.113.10`.
2. Подключитесь к нему: `ssh root@203.0.113.10`.
3. Установите Docker и Git, откройте нужные порты:
   ```bash
   apt update && apt install -y git ufw
   curl -fsSL https://get.docker.com | sh
   ufw allow 22 && ufw allow 80 && ufw allow 443 && ufw --force enable
   ```

## Шаг 2. Домен

В панели, где куплен домен, создайте две записи **A**. Обе указывают на IP сервера:

| Имя | Тип | Значение |
|---|---|---|
| `demo` | A | `203.0.113.10` |
| `console.demo` | A | `203.0.113.10` |

Получатся адреса `demo.ваш-домен` и `console.demo.ваш-домен`. Подождите, пока записи начнут работать: обычно минуты, иногда до часа. Проверить можно командой `ping demo.ваш-домен` — она должна показать IP сервера.

## Шаг 3. Код на сервер

Репозиторий закрытый, поэтому серверу нужен ключ только для чтения (deploy key):

```bash
ssh-keygen -t ed25519 -N "" -f ~/.ssh/nexus_sign_deploy
cat ~/.ssh/nexus_sign_deploy.pub
```

Добавьте этот ключ на GitHub: репозиторий → **Settings → Deploy keys → Add deploy key**. Галочку «Allow write access» **не ставьте**. Затем на сервере:

```bash
GIT_SSH_COMMAND="ssh -i ~/.ssh/nexus_sign_deploy" git clone git@github.com:ptrvalina/nexus-sign.git /opt/nexus-sign
cd /opt/nexus-sign
git config core.sshCommand "ssh -i ~/.ssh/nexus_sign_deploy"
```

## Шаг 4. Запуск в публичном режиме

```bash
cd /opt/nexus-sign
sandbox/bin/sandbox up --public demo.ваш-домен --email вы@ваш-домен
```

Первый запуск занимает 10–20 минут. Команда напечатает:

```
Phones:         https://demo.ваш-домен
Bank console:   https://console.demo.ваш-домен   first login operator / …, then operator / …
```

- **Консоль банка** защищена двумя паролями: сначала окно браузера (первая пара), затем страница входа консоли (вторая пара). Сохраните оба.
- **Публичный режим запоминается.** Последующие команды `sandbox/bin/sandbox up`, `down` и `status` работают с ним сами. Вернуться к локальному режиму: `sandbox/bin/sandbox public --off`.
- Откройте на телефоне `https://demo.ваш-домен` — должна открыться страница банка со ссылками на приложения.

> Сервер-песочница всё так же изолирован: PostgreSQL, Redis и Auth Core не видны из интернета. Наружу открыты только страница банка с API приложения и консоль за двумя паролями. Деньги тестовые, реальных платежей нет.

## Шаг 5. Логины тестировщиков

Каждому тестировщику — свой клиент: свой счёт с тестовыми деньгами и своя карта. Создать клиента можно двумя способами:

- **консоль → Клиенты → «Новый тестовый клиент»**: логин, имя, начальный остаток; или
- **на сервере:**
  ```bash
  sandbox/bin/sandbox add-customer ivan "Иван Петров" 10000
  ```

Пароль показывается **один раз** вместе с готовым текстом для тестировщика: логин, пароль, адрес банка, ссылка на скачивание. Забытый пароль: карточка клиента в консоли → «Выдать новый пароль».

## Шаг 6. Android: подписанный APK на странице банка

Это делается один раз. Нужен ключ подписи: без него телефоны не смогут обновлять приложение.

1. На своём Mac (нужна Java 17: `brew install openjdk@17`) выполните:
   ```bash
   cd ~/nexus-sign
   sandbox/mobile/android/make-release-key.sh
   ```
   Скрипт создаст файл `~/voxtel-sandbox-release.jks` и напечатает 4 значения. **Сохраните файл и пароль в надёжном месте.** Если их потерять, тестировщикам придётся удалять приложение и ставить заново.
2. На GitHub: репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Создайте 4 секрета с именами и значениями, которые напечатал скрипт:
   - `VOXTEL_ANDROID_KEYSTORE_BASE64`
   - `VOXTEL_ANDROID_KEYSTORE_PASSWORD`
   - `VOXTEL_ANDROID_KEY_ALIAS`
   - `VOXTEL_ANDROID_KEY_PASSWORD`

Каждый выпуск:

1. GitHub → **Actions → «sandbox apps (release)» → Run workflow**:
   - **server** = `https://demo.ваш-домен`;
   - **platforms** = `android` (или `both`).
2. Когда сборка закончится, скачайте в ней артефакт **voxtel-demo-apk** — это zip, внутри `app-release.apk` — и перенесите файл на сервер:
   ```bash
   scp app-release.apk root@203.0.113.10:/tmp/
   ssh root@203.0.113.10 "cd /opt/nexus-sign && sandbox/bin/sandbox publish-apk /tmp/app-release.apk"
   ```
3. На странице `https://demo.ваш-домен` появится кнопка **«Скачать APK»**. Адрес банка уже встроен в приложение.

> Кнопка «Run workflow» появится только после того, как PR с этим кодом влит в `main`: GitHub показывает ручные запуски только из основной ветки.

## Шаг 7. iPhone: TestFlight

### 7.1 Аккаунт Apple Developer на компанию

1. **Номер D-U-N-S.** Для регистрации компании Apple требует номер D-U-N-S. Он бесплатный. Проверьте, нет ли его уже у компании, или запросите на https://developer.apple.com/support/D-U-N-S/. Номер выдают до 5 рабочих дней, и ещё до 2 рабочих дней Apple получает данные.
2. **Что понадобится:**
   - официальное название компании — **Nexis Trust Technologies AG**; именно оно будет указано продавцом в App Store;
   - рабочий e-mail на домене компании;
   - сайт компании;
   - Apple ID с двухфакторной защитой;
   - право подписывать за компанию (владелец, руководитель или доверенность).
3. **Регистрация:** https://developer.apple.com/programs/enroll/ → «Start your enrollment» → организация. Оплата 99 $ в год.
4. **Возможные сложности.** Apple предупреждает, что в некоторых регионах регистрация недоступна из-за санкций. На форумах Apple много сообщений о зависших заявках из России и Беларуси. Надёжнее оформлять на компанию, её адрес и банковскую карту не из этих стран.

### 7.2 Подготовка App Store Connect (один раз)

1. **Создайте приложение:** https://appstoreconnect.apple.com → **Apps → «+» → New App**:
   - Platform: iOS;
   - Name: например «VoxTel Demo Bank»;
   - Bundle ID: создайте `com.nexis.voxtel.sandbox.bank`. Если идентификатор занят, придумайте свой и сохраните его в GitHub как **переменную** (Settings → Secrets and variables → Actions → **Variables**) с именем `VOXTEL_IOS_BUNDLE_ID`.
2. **Создайте ключ API:** **Users and Access → Integrations → App Store Connect API → «+»**, роль **App Manager**. Скачайте файл `AuthKey_XXXX.p8` (скачать можно только один раз) и запишите **Key ID** и **Issuer ID**.
3. **Узнайте Team ID:** https://developer.apple.com/account → Membership details.
4. **Добавьте 4 секрета в GitHub:**

   | Секрет | Значение |
   |---|---|
   | `APPLE_TEAM_ID` | Team ID |
   | `APP_STORE_CONNECT_KEY_ID` | Key ID |
   | `APP_STORE_CONNECT_ISSUER_ID` | Issuer ID |
   | `APP_STORE_CONNECT_KEY_P8` | всё содержимое файла `.p8`, вместе со строками BEGIN и END |

### 7.3 Выпуск сборки

1. GitHub → **Actions → «sandbox apps (release)» → Run workflow**: **server** = `https://demo.ваш-домен`, **platforms** = `ios` (или `both`). Сборка сама подпишется и загрузится в App Store Connect.
2. Через 5–30 минут сборка появится в App Store Connect → ваше приложение → **TestFlight**.
3. **Шифрование.** В приложении уже указано, что оно использует только стандартное шифрование (HTTPS и подписи для аутентификации). Это позволяет не загружать документы по экспорту шифрования. Если ваш юрист считает иначе, поменяйте ответ в App Store Connect.

### 7.4 Публичная ссылка для тестировщиков

1. TestFlight → **External Testing → «+»**: создайте группу, например «Тестировщики», и добавьте в неё сборку.
2. **Test Information:**
   - описание;
   - e-mail для отзывов;
   - **Sign-In Information**: создайте Apple отдельный тестовый логин (`sandbox/bin/sandbox add-customer apple-review "App Review" 10000`) и укажите его вместе с паролем. В заметках для проверяющего напишите: «Bank address is prefilled. Tap "Подключить телефон" after login.»
3. Первая сборка уходит на **проверку Apple** (Beta App Review), обычно до суток. **Сервер должен работать** — проверяющий будет входить в приложение.
4. После одобрения откройте группу → **Create Public Link → Open to Anyone**. Получится ссылка вида `https://testflight.apple.com/join/AbCdEf12`.
5. Покажите её на странице банка:
   ```bash
   sandbox/bin/sandbox testflight https://testflight.apple.com/join/AbCdEf12
   ```

Тестировщик ставит приложение **TestFlight** из App Store, открывает вашу ссылку и нажимает «Установить». Через публичную ссылку можно пригласить до 10 000 тестировщиков. Сборка TestFlight работает 90 дней, поэтому раз в 2–3 месяца выпускайте новую (шаг 7.3).

## Шаг 8. Что отправить тестировщику

Скопируйте текст, который консоль выдаёт при создании клиента, и добавьте одну строку:

```
VoxTel Demo Bank (демо)
Логин: ivan
Пароль: ••••••••
Адрес банка в приложении: https://demo.ваш-домен
Скачать приложение: https://demo.ваш-домен/
Откройте ссылку на телефоне: для iPhone — через TestFlight, для Android — «Скачать APK».
```

На телефоне тестировщик:

1. ставит приложение;
2. входит логином и паролем (адрес банка уже указан);
3. нажимает **«Подключить телефон»** и подтверждает Face ID или отпечатком;
4. делает перевод и подтверждает его.

Вы видите каждый шаг в консоли: **Транзакции → операция → хронология**.

## Обслуживание сервера

```bash
cd /opt/nexus-sign
git pull && sandbox/bin/sandbox up          # обновление (данные сохраняются)
sandbox/bin/sandbox status                  # что запущено
sandbox/bin/sandbox logs bank               # журнал банка (или caddy, auth-core)
sandbox/bin/sandbox reset && sandbox/bin/sandbox up   # стереть все демо-данные и начать заново
```

- **Логины после `reset`.** `reset` стирает и логины тестировщиков, поэтому их нужно создать заново, а тестировщикам — снова нажать «Подключить телефон». Пароли консоли сохраняются.
- **`--allow-unpinned`.** Если после `git pull` код Auth Core изменился, песочница попросит подтвердить версию. Запустите `sandbox/bin/sandbox up --allow-unpinned` или зафиксируйте версию командой `sandbox/bin/sandbox pin`.
- **Резервная копия** не нужна: это демо, и всё воссоздаётся командой `reset`.

## Если что-то не работает

| Признак | Что сделать |
|---|---|
| `https://demo.ваш-домен` не открывается | `ping demo.ваш-домен` показывает IP сервера? Порты 80/443 открыты (`ufw status`)? Журнал Caddy: `sandbox/bin/sandbox logs caddy` — там видно, получен ли сертификат |
| Браузер ругается на сертификат | DNS ещё не обновился или Let's Encrypt временно ограничил выдачу. Подождите и посмотрите журнал Caddy |
| Консоль просит пароль два раза | так задумано: окно браузера — первый пароль (`console-gate-password`), страница консоли — второй (`console-password`). Оба лежат в `/opt/nexus-sign/sandbox/.state/` |
| Сборка «sandbox apps (release)» падает на «secret … is missing» | не добавлен один из секретов (шаги 6 и 7.2) |
| iOS-сборка падает на подписи | Bundle ID в App Store Connect совпадает с `com.nexis.voxtel.sandbox.bank` или с переменной `VOXTEL_IOS_BUNDLE_ID`? У ключа API роль App Manager? |
| Android: «приложение не установлено» при обновлении | сборка подписана другим ключом. Используйте тот же `.jks`, а этот раз удалите приложение и поставьте заново |
| Тестировщик: «Нет связи с банком» | адрес в приложении — `https://demo.ваш-домен`, без порта; сервер запущен (`sandbox/bin/sandbox status`) |
