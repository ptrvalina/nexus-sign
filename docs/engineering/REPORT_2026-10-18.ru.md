# NEXUS-SIGN 2.0.0 — отчёт о работе, 18.10.2026

Ветка `remediation/2.0.0` локального репозитория. Коммиты `7c1c0a8`, `9dee0af` сделаны в этой сессии поверх `fa72341`. Это **не** коммиты GitHub: доступа к `ptrvalina/nexus-sign` из этой среды нет.

## 1. Что сделано

### Звонки (FI-001, ADR 0017)

**Auth Core**
- Порядок сигналов проверяется атомарно, одним Lua-скриптом в Redis:
  - offer присылает только телефон, и только когда предыдущий offer получил ответ;
  - answer присылает только оператор;
  - ICE-кандидаты принимаются после SDP отправителя;
  - после `bye` от стороны больше ничего не принимается.
- `messageId` защищает от двойной доставки при повторной отправке.
- Если сессия закрыта где-то ещё, обе стороны получают `bye` от `server`: решение оператора, истечение срока, подтверждение или отклонение авторизации, отзыв ключа.
- Новый маршрут `release`: оператор кладёт трубку без результата.
- Ключи Redis одного звонка находятся в одном слоте Redis Cluster.

**Консоль оператора**
- Отвечает на повторные offer (ICE restart).
- При «Положить трубку» сессия закрывается.
- Отправка сигналов повторяется при сбоях сети.

**Основные SDK (Kotlin и Swift), без зависимости от WebRTC**
- `openVerificationCall` открывает сессию; перед этим проверяются подписанные байты платежа.
- Сигнализация подписывается ключом устройства.
- `VerificationCallController` реализует логику звонка:
  - offer первым, буферизация кандидатов в обе стороны;
  - игнорирование дублей и устаревших сообщений;
  - ICE restart после обрыва, не больше двух раз;
  - завершение по `bye` или по сроку сессии;
  - освобождение камеры и микрофона ровно один раз.

**Модули медиа: `android-sdk-calls` и `ios-sdk-calls`**
- Используют нативные API libwebrtc.
- Разрешения на камеру и микрофон запрашиваются только перед звонком.
- Экран звонка показывает условия платежа и постоянный индикатор камеры и микрофона.
- При уходе приложения в фон камера останавливается; при закрытии экрана звонок завершается.
- Видео ограничено кодеками VP8 и VP9 (без H.264).

**Демо**
- Демо-банк может потребовать видео- или аудиозвонок для платежа.
- Оба демо-приложения проводят звонок до подписи.

**CI**: новые задачи `android-sdk-calls`, `ios-sdk-calls`, `sdk-call-conformance`.

### Безопасность

| Находка | Что сделано | Статус |
|---|---|---|
| FI-005 | В зашифрованном секрете указан идентификатор мастер-ключа. Предыдущие ключи задаются в `*_PREVIOUS`. Инструмент `rotateSecretKeys.js` перешифровывает все секреты новым ключом. Миграция 020 разрешает менять шифротекст офлайн-ключа только этому инструменту | Частично: обёртка ключей в HSM не сделана |
| FI-004 | `OFFLINE_CONFIRMATION_MAX_AMOUNT` ограничивает сумму офлайн-подтверждения по каждой валюте; в продакшене параметр обязателен | Частично: риск принципиальный, он ограничен, но не устранён |
| FI-008 | Одноразовые nonce запросов устройства хранятся в PostgreSQL (миграция 021) | Исправлено для nonce. Токены BOOTSTRAP по-прежнему в Redis |
| FI-019 | Каждая новая голова цепочки доказательств уходит банку вебхуком `evidence.appended` с подписью HSM. `verify-evidence --heads` находит удалённый «хвост» цепочки | Исправлено (банк должен хранить головы) |
| FI-030 | `/metrics` требует токен `METRICS_BEARER_TOKEN` | Исправлено |
| FI-023, FI-032 | Комментарии в коде и формулировки в README | Исправлено |

Libwebrtc распространяется под BSD-3-Clause с патентным грантом Google. Внутри сборок есть сторонние компоненты со своими лицензиями (BoringSSL, Opus, libvpx, abseil и др.), и их состав в закреплённых бинарниках **не установлен**. Патенты на H.264 грантом не покрываются: наши модули этот кодек не используют, но код в бинарнике может присутствовать.

Все открытые вопросы (TPM-1…TPM-7) блокируют продакшен: `docs/engineering/THIRD_PARTY_MEDIA.md`.

## 5. Блокеры

- **iOS**: нет сборки SDK, модуля звонков и демо; Swift-код не компилировался. Нужен прогон CI или Xcode на вашем Mac.
- **Android**: нет сборки Gradle; модуль звонков не собран против настоящего AAR.
- **Устройства**: ничего не запускалось. Чек-лист: `DEVICE_ACCEPTANCE_CHECKLIST.md`.
- **TURN**: есть эталонная конфигурация coturn и тесты учётных данных. Через настоящий TURN и мобильную сеть звонки не проверялись.
- **Консоль оператора**: проверена в Chromium; нет регламента для персонала банка.
- **HSM**: только SoftHSM; мастер-ключи не обёрнуты в HSM.
- **Lockfile** отсутствует, сканирование зависимостей не выполнялось.
- Юридическая оценка и независимый аудит безопасности не проводились.
